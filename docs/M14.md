# M14: Local/Global Macros, Scalars, and Loops

## Context

Dodo translates Stata `.do` commands to SQL via a CTE chain. Currently it handles 42 commands but has no support for macros or loops (M14 in PLAN.md). These are essential for real-world .do files that use `local`/`global` for parameterization and `foreach`/`forvalues` for repetitive operations.

## Scope

### Implementing
- `local name value` / `local name = expr` / `local name "string"`
- `global name value` / `global name = expr` / `global name "string"`
- `` `name' `` expansion (locals), `$name` / `${name}` expansion (globals)
- `local ++name` / `local --name`
- `macro drop name [name...]` / `macro drop _all`
- `scalar [define] name = expr` / `scalar list` / `scalar drop`
- `scalar(name)` in expressions
- `foreach lname in list { body }`
- `foreach lname of local macname { body }`
- `foreach lname of global macname { body }`
- `foreach lname of numlist spec { body }`
- `forvalues lname = #1(#d)#2 { body }` / `forvalues lname = #1/#2 { body }`
- `display "text"` / `display expr`

Also implementing:
- `tempvar lclname [...]` — assigns unique column names to local macros; columns with these names are dropped when the do-file/scope ends
- `tempname lclname [...]` — assigns unique scalar/macro names to local macros; cleaned up at scope end
- Macro functions (via `` `=expr' `` or `:macro_fcn` syntax):
  - `:variable label varname` — returns variable label from `state.variable_labels`
  - `:value label varname` — returns value label name from `state.column_labels`
  - `:label labelname # [#_2]` — returns label text for a value from `state.value_label_defs`
  - `:word count string` — returns number of space-separated tokens
  - `:word # of string` — returns the #th token
  - `:type varname` — returns storage type (maps to DuckDB types)
  - `:display fmt expr` — returns formatted result

### Runtime values via SET VARIABLE

All `=` assignments emit `SET VARIABLE` SQL — the compiler does not evaluate
expressions. Runtime-dependent tokens (`_N`, `r()`, `e()`) are handled
naturally since DuckDB evaluates the SET VARIABLE at runtime:

- `local n = _N` → `SET VARIABLE _dodo_l_n = (SELECT count(*) FROM ...)`
- `local a = 300` → `SET VARIABLE _dodo_l_a = 300`
- `scalar hi = r(max)` → deferred to M14c (stored results as tables)
- `forvalues i = 1/r(N) { ... }` → error: loop bound depends on runtime value

Loop bounds must still be compile-time known. See `docs/VARIABLE_SUBSTITUTION.md`.

### NOT implementing (M14a)
- Stored results (`r()`, `e()`) — see M14c plan in `docs/VARIABLE_SUBSTITUTION.md`
- `levelsof` — see M14b
- `macval()`, `macro shift`, `macro dir`, `macro list`
- `:subinstr`, `:piece`, `:strlen`, `:permname`, `:adosubdir`, `:dir`, `:sysdir`, `:environment`
- `:constraint`, `:char`, `:sortedby`, `:data label`, `:format`
- `:properties`, `:results`, matrix-related macro functions
- `:tsnorm`, `:copy`, `:list` (macro list directives)
- `foreach of varlist` / `foreach of newlist` (need column existence checks at parse time)

## Architecture

### Key Insight
Macros and scalars use a **unified symbol table** with LITERAL (text) and
VARIABLE (SET VARIABLE-backed) entries. Text substitution operates BEFORE
the command pipeline. Loops are **block accumulation + repeated execution**.

### Processing Pipeline (new steps marked with *)

```
1. Read line
2. Handle comments, /// continuation
3. * ExpandMacros() — substitute `name', $name, bare scalars
     LITERAL symbols → substitute text directly
     VARIABLE symbols → substitute getvariable('<uname>')
4. * Detect foreach/forvalues → accumulate brace block, execute iterations
5. IsDodoCommand() → recognize command
6. TokenizeCommand() → parse structure
7. ProcessCommand() → generate SQL
     local/global/scalar with = → emit SET VARIABLE, store {VARIABLE, uname}
     local/global without = → store {LITERAL, text}
```

## Implementation Plan

### Phase 1: Unified Symbol Table

**`src/core/dodo_core.hpp`** — Add types and replace maps in `DodoState`:
```cpp
enum class SymbolKind { LITERAL, VARIABLE };

struct SymbolEntry {
    SymbolKind kind;
    std::string value;  // LITERAL: text; VARIABLE: DuckDB variable name (_dodo_l_x)
};

// Replace local_macros, global_macros, scalars, set_variables with:
std::unordered_map<std::string, SymbolEntry> local_symbols;
std::unordered_map<std::string, SymbolEntry> global_symbols;
std::unordered_map<std::string, SymbolEntry> scalar_symbols;

std::vector<std::string> pending_sql;  // queued SET VARIABLE statements

// Tempvar/tempname tracking
std::vector<std::string> tempvar_columns;    // columns to DROP at scope end
std::vector<std::string> tempname_names;     // scalar/macro names to drop at scope end
int temp_counter = 0;                        // unique name generator: __dodo_tmp_0, __dodo_tmp_1, ...
```

**Helper methods on `DodoState`:**
- `GenerateUname(prefix, name)` → `"_dodo_" + prefix + "_" + name`
- `static ResolveSymbol(entry)` → `entry.value` for LITERAL, `getvariable('<entry.value>')` for VARIABLE

Clear these in `Clear()` and `ClearAll()`.

**`src/core/dodo_core.cpp`** — Update functions:
- `ExpandMacros(text, state)`: look up `local_symbols`/`global_symbols`/`scalar_symbols`, call `ResolveSymbol` to get substitution text. Remove `__SET_VAR__` checks.
  - `` `=expr' `` — evaluate expression inline via `EvaluateSimpleExpr` (compile-time only)
  - `` `:macro_fcn' `` — evaluate macro function
  - Bare scalar names → look up in `scalar_symbols`, resolve via `ResolveSymbol`
  - Iterate until no more expansions (depth limit 50).
- `EvaluateSimpleExpr(expr)`: kept for `` `=expr' `` inline macros and loop bounds only. Not used for `=` assignments.
- `EvaluateMacroFunction(func, state)`: unchanged.

**`src/core/dodo_core.cpp`** — Command handlers in `ProcessCommand()`:
- `local name value...` (no `=`): `local_symbols[name] = {LITERAL, value}`
- `local name = expr`: expand macros in expr, try `EvaluateSimpleExpr` → if success, `{LITERAL, result}`; if fail, generate uname, emit `SET VARIABLE <uname> = <expanded_expr>`, store `{VARIABLE, uname}`
- `local name = "string"`: `local_symbols[name] = {LITERAL, extracted_string}`
- `local ++name`: if LITERAL, increment text; if VARIABLE, emit `SET VARIABLE <uname> = getvariable('<uname>') + 1`
- `global`: same pattern with `global_symbols` and prefix `"g"`
- `scalar [define] name = expr`: same pattern with `scalar_symbols` and prefix `"s"`
- `scalar name = "string"`: `{LITERAL, extracted_string}`
- `scalar list` / `scalar drop`: use `scalar_symbols`
- `macro drop`: use new symbol maps
- `tempvar lclname [...]`: `local_symbols[lclname] = {LITERAL, tmpname}`
- `tempname lclname [...]`: `local_symbols[lclname] = {LITERAL, tmpname}`
- `display`: if expanded args contain `getvariable(`, emit `SELECT <expr> AS display`; otherwise `SELECT '<escaped>' AS display`
- `foreach v of local macname`: look up `local_symbols[macname]`, must be LITERAL (error if VARIABLE)
- Loop iteration variable: `local_symbols[lname] = {LITERAL, val}`

### Phase 2: Refactor Line Processing + Loops

**Eliminate duplication** between `ProcessDoFile()` and `process_stream()`. Extract shared `ProcessLines()`:

```cpp
using LineReader = std::function<bool(std::string &line)>;
std::vector<std::string> ProcessLines(LineReader reader, DodoState &state, bool skip_terminal);
```

Both `ProcessDoFile()` and `process_stream()` become thin wrappers providing a `LineReader`.

**Brace block accumulation** — `AccumulateBraceBlock(LineReader)`:
- Called when `{` detected at end of a foreach/forvalues line
- Reads lines until matching `}` (tracking brace depth for nested loops)
- Returns vector of body line strings
- Handles comments and `///` continuation within the block

**Loop execution** in `ProcessLines()`:
1. After macro expansion, detect `foreach`/`forvalues` prefix
2. Parse loop header (variable name, list type, list spec)
3. Accumulate body via `AccumulateBraceBlock()`
4. For each value: set `state.local_macros[lname]`, process each body line through the full pipeline (expand macros, dispatch command)
5. After loop: keep lname set to last value (Stata behavior)

**`ParseNumlist(spec)`** (~60 lines):
- `1/5` → 1 2 3 4 5
- `1(2)10` → 1 3 5 7 9
- Space-separated: `1 5 10` → 1 5 10
- Combinations: `1/3 10(5)25`

### Phase 3: REPL Integration

**`src/extension/dodo_extension.cpp`** — In `dodo_parser_override()`:
- Apply `ExpandMacros()` to each statement before dispatch
- For loop commands: construct a `LineReader` from the `;`-split statement array. Loops in REPL use `;` as line separator within braces: `foreach x in a b c { gen y = 1 ; gen z = 2 }`
- Macros/scalars persist across REPL invocations via `DodoStateInfo`

### Phase 4: CLI (dodoc.cpp)

- Replace `process_stream()` body with call to `ProcessLines()` using istream `LineReader`
- ~20 lines net change (mostly deletion of duplicated code)

## Key Design Decisions

1. **Macro expansion before command recognition** — ensures `` keep `varlist' `` works when `varlist` is a macro containing column names.

2. **Unified symbol table with LITERAL/VARIABLE distinction** — each symbol is either text (LITERAL, substituted directly) or a DuckDB variable name (VARIABLE, resolved via `getvariable()`). No `__SET_VAR__` markers, no separate `set_variables` set.

3. **`=` expressions try compile-time evaluation first** — the expression parser attempts to evaluate the RHS after macro expansion. If fully resolvable (all literals), the symbol is LITERAL. If not (runtime references like `_N`, `getvariable()`), the compiler emits `SET VARIABLE` and stores VARIABLE. This keeps loops and simple arithmetic fully compile-time.

4. **Namespace isolation via unique names** — `_dodo_l_x`, `_dodo_g_x`, `_dodo_s_x` ensure that `local x`, `global x`, and `scalar x` coexist without collision.

5. **Each loop iteration adds CTE steps normally** — `foreach x in a b { generate y_`x' = 1 }` adds 2 steps. This is correct: each generate transforms the dataset.

6. **`scalar(name)` and bare scalar names expanded in `ExpandMacros()`** — `ResolveSymbol` handles both LITERAL and VARIABLE entries. No changes needed to `TranslateExpression()`.

7. **REPL loops via `;` within braces** — natural fit since REPL already splits on `;`.
